# aero-signal 产品需求文档

本文是 Aero Signal 的产品事实与验收基线。

## 1. 产品定义

`aero-signal` 是部署在服务器上的微信公众号文章采集、清洗、归档与分组 API 服务。它只有一个系统管理员账号；所有需要操作后台的人使用这一账号。系统不提供公开注册、普通用户、计费、订阅、阅读前台或多角色授权。

产品以两类对象工作，名称不得混用：

- **监测公众号**：需要发现更新、配置等级并产出文章的目标公众号。
- **采集登录账号**：经管理员扫码授权、供某个已验收 connector 使用的登录会话；它不是监测公众号。

目标是：每天在 08:00 开始前生成一份可信的服务健康快照；根据监测公众号的心跳与等级判断当天应抓取的对象；将合规发现到的文章抓为清洗后的 Markdown 和正文图片；通过分组 API 稳定提供给内部服务。

## 2. 目标、非目标与约束

### 2.1 目标

- 唯一管理员可维护自身登录账号和密码、采集登录账号、监测公众号、抓取计划、代理、分组和 API Token。
- 添加监测公众号时以文章链接解析身份，并立即验证性抓取**最新可发现的前三篇不同文章**；三篇均不要求成功，但至少一篇全文验证成功才可进入“待配置”。
- 管理员设置首次自动抓取时间；该时间是后续心跳节奏的锚点。
- 每天先做一次预检和健康快照，再执行当天计划；不得在每个任务前重复全量探测。
- 文章保存原文链接、抓取时标题、清洗后的 Markdown 正文、正文图片、OCR 回填文本和完整版本历史。
- 外部内部服务仅通过分组 API 获取文章和健康快照；没有计费流程。

### 2.2 非目标

- 不创建第二个管理员，不提供注册、邀请、角色、会员或付费。
- 不承诺或实现验证码破解、WAF 绕过、鼠标模拟、设备指纹轮换、被平台限制后自动换 IP 继续访问。
- 不把公众号后台管理页面或微信读书的非公开网络请求写成稳定公开 API；具体 connector 必须在部署前完成授权和验收。
- 不做文章推荐、读者前台、赛事判断或 AI 内容生成。

### 2.3 单管理员规则

首次部署从受保护的部署配置创建唯一记录 `system_administrator`，账号与初始密码不得写入仓库或日志。首次登录必须修改密码；管理员可以修改账号和密码，不能删除、禁用或新增管理员。共享账号意味着审计只能证明“系统管理员会话”及时间/来源，不能识别具体操作者，界面必须明确提示这一限制。

| 内容校正 | 打开文章、编辑文字或重新抓取/OCR | 新版本被保存并从 API 增量输出 |
| 数据交付 | 创建分组和 Token | 接收方只能读取组内文章及健康快照 |

## 5. 采集登录账号与二维码登录

### 5.1 前提与流程

管理员先选择 connector 类型（`mp_admin` 或经部署验收的 `weread`）及固定出口；没有配置固定出口时使用本机出口。点击“扫码登录”后：

1. 服务端为该 connector 在绑定出口上创建短期二维码会话，生成不可猜测的 `login_ticket`。
2. 服务端返回二维码 data URL、到期时间和 `login_ticket`；前端仅用 `<img>` 展示 data URL，并每 2–3 秒读取会话状态。
3. 状态依次为 `waiting`、`scanned`、`confirmed`、`expired`、`failed`、`cancelled`。`scanned` 必须明确提示“请在手机确认”。
4. 确认后 connector 在同一会话和同一固定出口上完成登录，读取其可用的会话凭据与账号展示名；凭据写入 secrets/profile 存储，数据库只保存引用、过期时间、账号标识和固定出口绑定。
5. 登录成功后执行一次轻量授权验证；成功才创建 `active` 采集登录账号，失败则不留下可用账号。

二维码 ticket、临时 cookies、二维码内容和登录 token 只存 Redis/密钥存储并随到期或取消删除，不进入浏览器地址栏、日志、审计详情或数据库 JSON。二维码失效、退出或固定出口更换后必须重新扫码。

### 5.2 connector 事实边界

- `mp_admin` 只能使用管理员确实被授权管理的公众号后台能力；不能声明可枚举任意第三方公众号。
- `weread` 仅在部署方提供合法、已验收的授权 connector 后启用。它的实际能力（发现链接或返回全文）由 capability probe 决定，未通过 probe 的账号不能被计划使用。
- 文章详情始终按文章 URL 独立抓取；不得把采集登录账号的 token 附加到文章 URL。

## 6. 添加监测公众号与首次验证

1. 管理员粘贴公众号历史文章链接。
2. 系统提取并规范化 `__biz`、`mid`、`idx`、`sn`、名称和样例 URL；以强标识去重。已有公众号直接打开详情，不创建重复记录。
3. 系统用已通过预检且通道兼容的采集登录账号，发现最新候选文章，并按文章唯一键取前 3 篇；不足三篇时抓取可发现的全部篇数并如实显示。
4. 三篇各自走“全文抓取 → 图片清洗 → OCR → Markdown”链路。验证不能因单篇失败中断其他篇。
5. 至少一篇成功：公众号进入 `pending_configuration`，管理员必须设置等级、时间窗口和首次自动抓取时间；零篇成功：进入 `needs_action`，不得生成日常计划。
6. 管理员设置的首次时间写入 `first_heartbeat_at` 与 `next_heartbeat_at`；系统从此时间计算后续到期，不以“添加时间”偷换。

新增数量过多仅显示“建议今日分批添加”的提醒，绝不阻止添加。首次验证抓取和正常计划各自幂等，重复点击不会重复存文章。

## 7. 等级、心跳与降级规则

等级表示探测节奏，不表示内容价值。管理员可覆盖某个公众号的间隔、窗口、通道和下次时间。

| 等级 | 默认 connector | 基础心跳间隔 | 连续无新文章后的动作 |
| --- | --- | --- | --- |
| LO0 | 已验收 weread connector | 1 天 | 不自动降级；仅管理员移出 |
| LO1 | 已验收 weread connector | 1 天 | 不自动降级；仅管理员移出 |
| L1 | mp_admin 或已验收替代 connector | 2 天 | 连续 2 次空抓后延至 3 天；连续 4 次转 L2 |
| L2 | mp_admin 或已验收替代 connector | 7 天 | 连续 2 次空抓后延至 10 天；连续 4 次转 L3 |
| L3 | mp_admin 或已验收替代 connector | 30 天 | 连续 4 次空抓后保持 L3，并标记低活跃 |
| L4 | 无 | 不计划 | 管理员手动恢复前不抓取 |

一次心跳执行后的规则：

- 发现至少一篇新文章：`consecutive_empty_fetches=0`，按该等级基础间隔计算下次心跳；L2/L3 可临时提升为 L1，默认持续 14 天，管理员可关闭自动提升。
- 成功执行但没有新文章：空抓计数加一，按上表延期；每次延期都写明“为何今天未抓/为何下次延期”。
- connector、网络或临时下载失败：不计为空抓，进入有限退避重试；重试耗尽进入 `needs_action`，保持等级与空抓计数。
- 平台限制、验证码、授权失效：不自动切换 connector 或动态出口规避，进入 `needs_action`。
- 手动“立即抓取”不改变首次锚点；成功发现新文章可重置空抓计数，管理员可选择是否据此重算下次心跳。

## 8. 每日计划与健康快照

每日固定节奏（时区来自设置）：

1. **07:30**：执行一次 `daily_preflight`，检测采集登录账号、其绑定固定出口、动态出口可用性、connector capability 和任务 worker；不得抓取监测公众号文章。
2. **07:45 前**：固化当天 `service_health_snapshot`，包含各账号可否抓取、不可用原因、昨日计划和文章任务的成功/失败数、待处理数、可用出口数与生成时间。
3. **08:00**：根据 `next_heartbeat_at <= 当日结束` 且预检可执行的公众号生成当日计划。
4. 计划仅落在管理员配置的工作窗口。系统按窗口容量加权随机抽样，而不是均分为固定间隔；同一公众号和同一采集登录账号仍受串行/并发预算约束。
5. 到点创建抓取任务。运行期只记录任务结果；不重新进行全量健康检查。

管理员可手动触发“立即检查”或“重建今天计划”；前者产生单对象检查记录，后者不覆盖已经开始的任务。健康快照是当天的事实记录，不能被随后单个任务的状态静默改写。

## 9. 文章抓取、清洗与 OCR

### 9.1 全文与懒加载图片

详情任务按 canonical URL 抓取文章；若静态 HTML 不完整，浏览器 runtime 在同一合规会话中等待正文并滚动正文容器，收集懒加载属性中的原图 URL。不得依赖固定 `src`，也不得下载正文外的页面装饰资源。

正文图片必须同时满足以下规则才入库并进入 Markdown：位于正文 DOM、不是隐藏/跟踪/表情资源、不是重复出现的头图或尾图、并达到设置中的最小尺寸或最小面积。默认建议 `min(width,height) >= 80px` 且 `width × height >= 14,400px²`；管理员可调整阈值、白名单或在文章详情中人工保留/删除。阈值判断以下载后的实际尺寸为准。

### 9.2 OCR 与 Markdown

- HTML 文本先解析为正文块；每张保留的正文图片单独 OCR。
- OCR 结果按图片原位置插入 Markdown，标注为图片文字块；低置信度内容不得伪装为原文，须标明并允许重跑/编辑。
- `content_md` 是唯一对外的正文格式，包含正文、受控本地图片引用和 OCR 文本；不向外输出原始 HTML。
- 管理员手动编辑 Markdown、重跑 OCR、按原文链接重新抓取都会创建文章新 revision，保留抓取版与人工版差异。

### 9.3 去重与重抓

文章主唯一键为 `source_id + __biz + mid + idx`；无法取得时退回 canonical URL。内容 hash 仅用于发现内容相同，不得单独作为全局文章唯一键。重复发现只更新发现记录，不生成重复文章；重新抓取内容、图片或人工编辑发生变化时才产生 revision 与 change event。

## 10. 分组 API 与健康 API

分组只选择监测公众号，不能改变其抓取规则或复制文章。每个 Token 绑定一个分组、范围、可选调用方 IP allowlist 和有效期；明文 Token 仅在创建时显示一次。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/articles` | 读取组内文章 | `articles:read` |
| `GET /api/articles/{id}` | 读取文章全文与图片引用 | `articles:read` |
| `GET /api/articles/since` | 以 `change_sequence` 增量读取 | `articles:read` |
| `GET /api/sources` | 读取组内公众号摘要 | `sources:read` |
| `GET /api/service-health/latest` | 读取最新每日健康快照 | `service_health:read` |
| `GET /api/service-health?date=YYYY-MM-DD` | 读取指定保留期内快照 | `service_health:read` |

健康 API 返回快照日期、生成时间、总体 `healthy/degraded/unhealthy`、每个采集登录账号/connector/出口的状态、昨日抓取成功失败数、今日计划数和待处理项；绝不返回 Cookie、token、代理地址或敏感错误正文。

## 11. 代理与设置

- **本机出口**是默认选项。
- **固定出口**可配置多个，只用于二维码登录、维持登录态和 connector 列表发现；采集登录账号一旦扫码成功即绑定出口。管理员手动切换或预检发现网络不可达时才按优先级切换，并标记为需重新扫码。
- **动态出口**可配置多个，只用于文章正文/图片下载。支持静态端点、供应商网关和供应商分配 API；密钥只保存引用。网络不可达时可切换健康的下一出口；目标站限制不触发切换。
- 设置页可管理供应商、端点、优先级、启停、用途、测试和健康历史；不能查看已保存密码。

## 12. 状态、异常与审计

关键状态：采集登录账号 `qr_waiting/active/expired/disabled/needs_relogin`；监测公众号 `verifying/pending_configuration/active/paused/needs_action`；计划 `planned/running/succeeded/retry_wait/failed/needs_action/skipped`；文章 `captured/normalized/ocr_pending/ready/ready_with_ocr_warning/edited/withdrawn`。

必须审计：管理员账号或密码变更、二维码会话创建/取消/确认、固定出口绑定变更、公众号添加与规则变更、首次验证、计划重建、手动抓取/重抓/OCR、文章编辑、分组/Token/代理/API 设置变更。审计不记录凭据、全文或代理密码。

## 13. 非功能要求与验收

- 所有长操作创建可恢复 job；前端刷新后能看到阶段、结果与待处理动作。
- 07:45 前无任务失败时仍须生成健康快照；08:00 后的抓取不得反复触发全量 preflight。
- 二维码超时、取消、手机拒绝、确认成功、登录验证失败均有前端可见状态和测试。
- 新增公众号验证只抓取最多三篇不同文章；重复提交不重复入库。
- 懒加载图片、装饰图片过滤、小图标过滤、OCR 回填、手工编辑和 revision 均有自动化测试。
- API cursor 重放不漏新增、编辑、重抓、图片变化或撤回，且下游可幂等消费。
- 服务在无可用采集登录账号、无可用出口、授权失效、平台限制时明确降级，不伪造“抓取成功”。
