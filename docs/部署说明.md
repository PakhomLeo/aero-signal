# Signal 部署说明（中文）

## 0. 运行环境与生产硬门禁

必须显式区分开发与生产：

```env
# 本地开发，可显式使用 Fake
SIGNAL_ENV=development

# 生产
# SIGNAL_ENV=production
```

`SIGNAL_ENV=production` 会在连接数据库前检查全部硬依赖，并禁止静默 Fake 回退。生产必须使用 PostgreSQL，并显式配置 `DATABASE_URL`、`REDIS_URL`、`SIGNAL_SECRET_STORE_PATH`、S3 endpoint/access key/secret key/bucket、`CLOAKBROWSER_CDP_URL`、已验收 connector 和真实 OCR provider。缺少任一项都会以稳定的 `config.*` 错误拒绝启动。

当前真实 OCR adapter 尚待修复计划 R05 接入，因此 production 会返回 `config.ocr_provider_not_implemented`。这是有意的安全门禁；不得通过改成 Fake 或删除校验绕过。Fake 二维码推进 API 也只在 test/development 路由中挂载，production 请求会得到 404。

## 1. 基础设施（本地）

```powershell
podman machine start
# 使用你自己的 compose 文件启动 PostgreSQL、Redis 和 MinIO
podman compose up -d
```

| 服务 | 端口 | 说明 |
| --- | --- | --- |
| PostgreSQL | 5432 | 用户 `aero` / 密码自行设置（示例占位 `change-me`，须与 `DATABASE_URL` 一致） |
| Redis | 6379 | 二维码 ticket 等短期状态 |
| MinIO | 9000 / 9001 | 对象存储 |
| CloakBrowser CDP | 9222 | 浏览器自动化（可选） |

Signal 专用库：`aero_signal_dev`。初始化：

```powershell
.\scripts\init-dev-resources.ps1
```

## 2. 环境变量

参考 `.env.example`：

| 变量 | 含义 |
| --- | --- |
| `SIGNAL_STORE` | `memory` \| `postgres`；未设时有 `DATABASE_URL` → postgres，否则 memory |
| `DATABASE_URL` | `postgres://aero:…@127.0.0.1:5432/aero_signal_dev`（postgres 模式必填） |
| `SIGNAL_EMBED_WORKER` | 仅 memory：`1` 时 HTTP 进程内嵌 Worker；**生产禁止依赖** |
| `SIGNAL_WORKER_ID` | Worker 进程标识（可选） |
| `SIGNAL_SCHEDULER` | Worker 日调度（默认 `1`）：07:30 preflight / 08:00 plan；设 `0` 关闭 |
| `SIGNAL_SECRET_STORE_PATH` | 密钥文件目录（postgres 默认 `./data/secrets`） |
| `REDIS_URL` | `redis://127.0.0.1:6379/0` |
| `REDIS_KEY_PREFIX` | **必须**使用产品前缀，默认 `signal:`，避免与其它 Aero 产品键冲突 |
| `S3_ENDPOINT` / `S3_ACCESS_KEY` / `S3_SECRET_KEY` | MinIO（path-style PUT，按 hash 去重） |
| `S3_BUCKET` | 默认 `aero-signal-dev` |
| `CLOAKBROWSER_CDP_URL` | 可选，如 `http://127.0.0.1:9222`；配置后文章抓取可走 CDP 真实页面 |
| `SIGNAL_MP_ADMIN_PROTOCOL` | 设为 `1` 启用 mp_admin 真实扫码登录与已发列表 API |
| `SIGNAL_LISTEN_ADDR` | 默认 `127.0.0.1:8080` |
| `SIGNAL_BOOTSTRAP_USERNAME` / `SIGNAL_BOOTSTRAP_PASSWORD` | 首次部署唯一管理员：两者均非空时，`signal-service` 启动时若库中尚无管理员则自动创建；**勿写入仓库或日志** |
| `SIGNAL_BOOTSTRAP_TOKEN` | `POST /api/admin/auth/bootstrap` 所需初始化口令（请求体 `bootstrap_token`，常量时间比较）；留空则禁用 HTTP bootstrap |
| `RUST_LOG` | 建议 `info,signal=debug` |

时区：业务调度默认 `Asia/Shanghai`（`system_settings.timezone`），与 07:30 preflight / 08:00 计划窗口一致。容器与宿主机建议同为东八区或显式设置 `TZ=Asia/Shanghai`。

## 3. Bootstrap 与双进程

1. 设置 `SIGNAL_BOOTSTRAP_USERNAME` / `SIGNAL_BOOTSTRAP_PASSWORD`（强密码），由 `signal-service` 启动时自动 bootstrap；或设置 `SIGNAL_BOOTSTRAP_TOKEN` 后调用 HTTP bootstrap。已有管理员时两种方式都会拒绝/跳过。
2. 迁移：`sqlx migrate run`，或启动 postgres 模式时由进程自动 Migrator。
3. 启动 HTTP：`cargo run -p signal-service --bin signal-service`。
4. 启动 Worker：`cargo run -p signal-service --bin signal-worker`（PG / 生产必开；memory 可用 `SIGNAL_EMBED_WORKER=1` 单进程联调）。
5. 首次登录必须改密；明文密码不得出现在日志/审计 details。

## 4. 迁移与验收命令

```powershell
$env:DATABASE_URL = "postgres://aero:change-me@127.0.0.1:5432/aero_signal_dev"
sqlx migrate run
cargo check --workspace
cargo test -p signal-service --lib
cargo test -p signal-service --tests
pnpm -C web build
```

## 5. Redis 前缀与 Bucket

- Redis 键一律带 `REDIS_KEY_PREFIX`（`signal:`）。
- 对象存储 bucket 与产品绑定：`aero-signal-dev`（生产另建并轮换密钥）。

## 7. Retention 说明

`failed_validation_asset` 策略首期**空转**（无独立资产表；验证失败落在 `source_validation_runs`）。迁移 `20260710000001` 将该策略 `enabled=false`。
